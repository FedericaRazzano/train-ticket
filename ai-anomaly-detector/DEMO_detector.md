## 1. Introduction

### What it does

`ts-ai-anomaly-detector` monitors the **Train Ticket** microservice mesh and detects
services that are behaving abnormally — for example a service with unusually high latency
or a high error rate.

It uses an **Isolation Forest**, a machine learning algorithm from scikit-learn that
learns what "normal" looks like from a set of baseline snapshots, and then flags any
service that deviates significantly from that baseline.

### What a "snapshot" is

A snapshot is a point-in-time picture of the service mesh: which services are talking to
which, how many calls per minute, the average latency of each call, and the error rate of
each service. Snapshots are collected from **Jaeger** (distributed traces) and
**Prometheus** (metrics). If neither is available, the service falls back to synthetic
data generated by `src/simulate_traces.py`.

### Effect on the system

**None.** The detector is completely passive. It reads from Jaeger and Prometheus but
never writes to any database, never modifies any request, never changes routing. You can
run it alongside a production Train Ticket cluster without any risk.

### When it is useful

- During a demo to show that the system can self-monitor
- When investigating a degradation (run `/scan` manually and see which service is flagged)
- As a continuous background monitor via the built-in Kubernetes CronJob

## 2. Architecture at a Glance

```
Every 2 minutes
     │
     ▼
┌─────────────────┐   POST /scan   ┌────────────────────────────────┐
│  Kubernetes     │ ─────────────► │  ts-ai-anomaly-detector        │
│  CronJob        │                │  (Flask on port 8080)          │
└─────────────────┘                │                                │
                                   │  1. collect_snapshot()         │
                                   │     ├─ Jaeger  :16686  (traces)│
                                   │     └─ Prometheus :9090 (metrics)
                                   │     (falls back to simulated   │
                                   │      data if unreachable)      │
                                   │                                │
                                   │  2. AnomalyDetector.detect()   │
                                   │     (Isolation Forest, pre-    │
                                   │      trained at startup)       │
                                   │                                │
                                   │  3. If anomalies found:        │
                                   │     └─ POST webhook alert      │
                                   │                                │
                                   │  4. Update Prometheus metrics  │
                                   │     (ai_anomaly_*)             │
                                   └────────────────────────────────┘
                                                  │
                                                  ▼
                                         ┌─────────────┐
                                         │   Grafana   │
                                         │  dashboard  │
                                         └─────────────┘
```

## 4. Part 1 — Local Testing (no Kubernetes needed)

The microservice can run entirely on your laptop. When Jaeger and Prometheus are not
reachable, it automatically falls back to synthetic data, so you will see realistic
output even without a live cluster.

### Step 1 — Navigate to the service directory

```bash
cd train-ticket/ai-anomaly-detector
```

### Step 2 — Upgrade pip and install dependencies

```powershell
# Upgrade pip first (required on Python 3.8 which ships with an old pip)
python -m pip install --upgrade pip

# Install all dependencies
python -m pip install -r requirements.txt
```

This installs Flask, gunicorn, scikit-learn, numpy, requests, prometheus-client, and
the OpenTelemetry packages listed in `requirements.txt`.

### Step 3 — Start the server

```bash
python app.py
```

You should see output similar to:

```
  [AnomalyDetector] Fitted on 200 samples from 20 snapshot(s).
INFO:__main__:Auto-trained Isolation Forest on 20 simulated normal snapshots.
INFO:werkzeug: * Running on http://0.0.0.0:8080
```

The server is now listening on port 8080. The Isolation Forest is already trained and
ready to detect anomalies. Leave this terminal open.

### Step 4 — Verify the server is running

Open a second terminal and run:

```bash
curl http://localhost:8080/health
```

Expected response:

```json
{
  "model_trained": true,
  "status": "ok"
}
```

`model_trained: true` confirms that the Isolation Forest trained successfully at startup.

### Step 5 — Run a scan

The `/scan` endpoint is the main entry point: it collects a snapshot (or generates a
synthetic one), runs the detector, and returns the results.

```bash
curl -X POST http://localhost:8080/api/v1/anomalydetector/scan
```

Example response (annotated):

```json
{
  "status": "ok",
  "collected_at": "2026-03-25T10:02:00",   // timestamp of the snapshot
  "source": "simulated",                    // "live" if Jaeger/Prometheus answered,
                                            // "simulated" if they were unreachable
  "model": "isolation_forest",              // detection algorithm used
  "anomalies_found": 1,                     // number of flagged services
  "results": [
    {
      "service": "ts-order-service",
      "anomaly_score": 0.8712,              // 0 = perfectly normal, 1 = very anomalous
      "is_anomaly": true,                   // true if score >= 0.5 (default threshold)
      "features": {
        "avg_latency_in_ms": 3021.4,        // mean inbound latency in milliseconds
        "calls_in": 95.0,                   // total inbound calls in this snapshot
        "calls_out": 67.0,                  // total outbound calls
        "error_rate": 0.118                 // fraction of 5xx responses (0–1)
      }
    },
    {
      "service": "ts-auth-service",
      "anomaly_score": 0.2341,
      "is_anomaly": false,
      "features": {
        "avg_latency_in_ms": 14.2,
        "calls_in": 85.0,
        "calls_out": 0.0,
        "error_rate": 0.003
      }
    }
    // ... one entry per service in the snapshot, sorted by anomaly_score descending
  ]
}
```

### Step 6 — Analyze a custom snapshot

Use `/analyze` when you already have a snapshot (e.g. collected by `data_collector.py`)
and want to score it without triggering a new collection.

First, generate a snapshot file:

```bash
python src/simulate_traces.py --normal 1 --print > my_snapshot.json
```

This writes one synthetic snapshot to `my_snapshot.json`. Now wrap it in the expected
request format and send it:

```bash
# Create the request body
python -c "
import json, sys
snap = json.load(open('my_snapshot.json'))
print(json.dumps({'snapshot': snap}))
" > request_body.json

curl -X POST http://localhost:8080/api/v1/anomalydetector/analyze \
     -H "Content-Type: application/json" \
     -d @request_body.json
```

On Windows PowerShell:

```powershell
python -c "
import json, sys
snap = json.load(open('my_snapshot.json'))
print(json.dumps({'snapshot': snap}))
" | Out-File -Encoding utf8 request_body.json

curl -X POST http://localhost:8080/api/v1/anomalydetector/analyze `
     -H 'Content-Type: application/json' `
     -d (Get-Content request_body.json -Raw)
```

### Step 7 — Retrain the model with your own data

By default the model trains on 20 synthetic normal snapshots. You can replace this
baseline by sending your own snapshots to `/train`:

```bash
# Generate 30 normal snapshots and save them
python src/simulate_traces.py --normal 30 --anomaly 0 --out-dir data/

# Build the training request and send it
python -c "
import json, glob
snapshots = [json.load(open(f)) for f in sorted(glob.glob('data/sim_*_normal.json'))]
print(json.dumps({'snapshots': snapshots}))
" | curl -X POST http://localhost:8080/api/v1/anomalydetector/train \
         -H "Content-Type: application/json" \
         -d @-
```

Expected response:

```json
{
  "status": "ok",
  "message": "Model trained on 30 snapshot(s)."
}
```

After this call, `/scan` and `/analyze` will use the new model.

### Step 8 — Read Prometheus metrics

```bash
curl http://localhost:8080/metrics
```

You will see standard Prometheus text format output. Look for lines starting with
`ai_anomaly_`:

```
# HELP ai_anomaly_scans_total Total scans run
# TYPE ai_anomaly_scans_total counter
ai_anomaly_scans_total_total 3.0

# HELP ai_anomaly_anomalies_found Anomalies found in last scan
# TYPE ai_anomaly_anomalies_found gauge
ai_anomaly_anomalies_found 1.0

# HELP ai_anomaly_service_score Per-service anomaly score
# TYPE ai_anomaly_service_score gauge
ai_anomaly_service_score{service="ts-order-service"} 0.8712
ai_anomaly_service_score{service="ts-auth-service"} 0.2341
```

These metrics are automatically scraped by Prometheus when the service is deployed in
Kubernetes (see [Grafana Dashboard](#10-grafana-dashboard)).

## 5. API Reference

### `GET /health`

Returns the current health status and whether the ML model is trained.

**Response:**

```json
{
  "status": "ok",
  "model_trained": true
}
```

---

### `GET /metrics`

Returns Prometheus metrics in text format. Used by the Prometheus scraper.

**Response:** Prometheus exposition format (text/plain).

**Metrics exposed:**

| Metric | Type | Description |
|---|---|---|
| `ai_anomaly_scans_total` | counter | Total number of `/scan` calls made |
| `ai_anomaly_anomalies_found` | gauge | Number of anomalous services in the last scan |
| `ai_anomaly_service_score{service="..."}` | gauge | Anomaly score (0–1) per service, last scan |

---

### `POST /api/v1/anomalydetector/analyze`

Analyzes a snapshot you provide. Does not collect data from Jaeger/Prometheus.

**Request body:**

```json
{
  "snapshot": {
    "collected_at": "2026-03-25T10:00:00",
    "nodes": [
      {
        "service": "ts-order-service",
        "call_count": 142,
        "p99_latency_ms": 3085.0,
        "error_rate": 0.12
      }
    ],
    "edges": [
      {
        "source": "ts-preserve-service",
        "target": "ts-order-service",
        "call_count": 40,
        "avg_latency_ms": 3021.4
      }
    ]
  }
}
```

**Fields:**

| Field | Required | Description |
|---|---|---|
| `snapshot.collected_at` | yes | ISO 8601 timestamp |
| `snapshot.nodes` | yes | List of services with their metrics |
| `snapshot.nodes[].service` | yes | Service name |
| `snapshot.nodes[].call_count` | yes | Number of spans/calls |
| `snapshot.nodes[].p99_latency_ms` | no | p99 latency from Prometheus (null if unavailable) |
| `snapshot.nodes[].error_rate` | no | Fraction of 5xx responses (null if unavailable) |
| `snapshot.edges` | yes | List of inter-service calls |
| `snapshot.edges[].source` | yes | Calling service |
| `snapshot.edges[].target` | yes | Called service |
| `snapshot.edges[].call_count` | yes | Number of calls on this edge |
| `snapshot.edges[].avg_latency_ms` | yes | Average latency in milliseconds |

**Response:** Same format as `/scan` (see Step 5 above), without `source` and
`collected_at` at the top level.

**Error responses:**

```json
{ "status": "error", "message": "Missing 'snapshot' field" }   // HTTP 400
```

---

### `POST /api/v1/anomalydetector/train`

Replaces the current Isolation Forest model with a new one trained on the snapshots you
provide. Send only **normal** (non-anomalous) snapshots for best results.

**Request body:**

```json
{
  "snapshots": [
    { "collected_at": "...", "nodes": [...], "edges": [...] },
    { "collected_at": "...", "nodes": [...], "edges": [...] }
  ]
}
```

At least one snapshot is required. The more you provide (20–50 recommended), the more
robust the model.

**Response:**

```json
{
  "status": "ok",
  "message": "Model trained on 30 snapshot(s)."
}
```

**Error responses:**

```json
{ "status": "error", "message": "Missing 'snapshots' field" }            // HTTP 400
{ "status": "error", "message": "'snapshots' must be a non-empty list" } // HTTP 400
{ "status": "error", "message": "<exception message>" }                  // HTTP 500
```

---

### `POST /api/v1/anomalydetector/scan`

Collects a fresh snapshot from Jaeger and Prometheus, analyzes it, updates Prometheus
metrics, and — if anomalies are found and a webhook is configured — sends an alert.

No request body is needed.

**Response:**

```json
{
  "status": "ok",
  "collected_at": "2026-03-25T10:02:00",
  "source": "live",
  "model": "isolation_forest",
  "anomalies_found": 1,
  "results": [
    {
      "service": "ts-order-service",
      "anomaly_score": 0.8712,
      "is_anomaly": true,
      "features": {
        "avg_latency_in_ms": 3021.4,
        "calls_in": 95.0,
        "calls_out": 67.0,
        "error_rate": 0.118
      }
    }
  ]
}
```

**`source` values:**

| Value | Meaning |
|---|---|
| `"live"` | Snapshot was collected from Jaeger and Prometheus |
| `"simulated"` | Jaeger/Prometheus were unreachable; synthetic data was used |

**`model` values:**

| Value | Meaning |
|---|---|
| `"isolation_forest"` | Trained ML model was used (normal case) |
| `"simple_threshold"` | Fallback rule-based detection (latency > 500ms or error rate > 5%) |

## 6. Configuration

The service reads its configuration from environment variables. All variables are
optional — sensible defaults are provided for in-cluster use.

| Variable | Default | Description |
|---|---|---|
| `JAEGER_URL` | `http://jaeger-query:16686` | Jaeger query endpoint |
| `PROMETHEUS_URL` | `http://prometheus:9090` | Prometheus endpoint |
| `ALERT_WEBHOOK_URL` | _(empty — disabled)_ | URL to POST alert payloads to |
| `OTEL_SERVICE_NAME` | `ts-ai-anomaly-detector` | OpenTelemetry service name (set by Dockerfile) |

### Setting variables locally (PowerShell)

```powershell
$env:JAEGER_URL      = "http://localhost:16686"
$env:PROMETHEUS_URL  = "http://localhost:30090"
$env:ALERT_WEBHOOK_URL = "https://your-endpoint.example.com/alert"

python app.py
```

### Setting variables in Kubernetes (values.yaml)

Open `manifests/helm/trainticket/values.yaml` and edit the `tsAiAnomalyDetector` section:

```yaml
tsAiAnomalyDetector:
  name: ts-ai-anomaly-detector
  secretRef: ts-ai-anomaly-detector
  lang: python
  alertWebhookUrl: "https://your-endpoint.example.com/alert"  # set your URL here
```

The Helm chart automatically injects `ALERT_WEBHOOK_URL` into the pod's Secret when
`alertWebhookUrl` is non-empty. For `JAEGER_URL` and `PROMETHEUS_URL`, the in-cluster
defaults work out of the box when the monitoring stack is deployed.

## 8. Automatic Scanning (CronJob)

Once deployed, a Kubernetes CronJob named `ts-ai-anomaly-scanner` runs automatically
every 2 minutes. It calls `POST /api/v1/anomalydetector/scan` on the service, which
triggers a full collect-detect-alert cycle.

### How it works

```
Every 2 minutes:
  kubectl job → curl -X POST http://ts-ai-anomaly-detector:8080/api/v1/anomalydetector/scan
                                            │
                              Response JSON printed to job pod logs
```

### Change the schedule

Edit `manifests/helm/trainticket/values.yaml`:

```yaml
anomalyScanner:
  enabled: true
  schedule: "*/5 * * * *"   # change this — standard cron syntax
  image: curlimages/curl:8.6.0
  monitoring: true
```

Cron syntax reference:

| Expression | Meaning |
|---|---|
| `*/2 * * * *` | Every 2 minutes |
| `*/5 * * * *` | Every 5 minutes |
| `0 * * * *` | Every hour |
| `0 9 * * 1-5` | 09:00 on weekdays |

Apply the change with `helm upgrade`.

### Disable the CronJob

```yaml
anomalyScanner:
  enabled: false
```

### View the results of past scans

```bash
# List the last 3 completed jobs
kubectl get jobs -n ts -l app=ts-ai-anomaly-scanner

# View the output of the most recent job
kubectl logs -n ts -l job-name=<job-name-from-above>
```

The log output is the raw JSON response from `/scan`, including `anomalies_found` and
the full `results` array.

## 9. Webhook Alerts

When the detector finds at least one anomalous service, it can send an HTTP POST to a
URL of your choice. This works with Slack incoming webhooks, Microsoft Teams connectors,
Discord webhooks, or any custom endpoint.

### Enable alerts

In `manifests/helm/trainticket/values.yaml`, set your webhook URL:

```yaml
tsAiAnomalyDetector:
  name: ts-ai-anomaly-detector
  secretRef: ts-ai-anomaly-detector
  lang: python
  alertWebhookUrl: "https://hooks.slack.com/services/YOUR/SLACK/WEBHOOK"
```

Then redeploy:

```bash
helm upgrade ts manifests/helm/trainticket -n ts \
  --set global.image.tag=latest
```

### Alert payload format

When anomalies are found, the following JSON is sent to your webhook URL:

```json
{
  "source": "ts-ai-anomaly-detector",
  "collected_at": "2026-03-25T10:02:00",
  "anomalies_found": 1,
  "anomalies": [
    {
      "service": "ts-order-service",
      "anomaly_score": 0.8712,
      "is_anomaly": true,
      "features": {
        "avg_latency_in_ms": 3021.4,
        "calls_in": 95.0,
        "calls_out": 67.0,
        "error_rate": 0.118
      }
    }
  ]
}
```

Only services where `is_anomaly: true` are included in the `anomalies` array.

### Test alerts locally

Run a minimal HTTP echo server in one terminal:

```bash
python -m http.server 9999
```

In a second terminal, start the Flask service with the webhook pointing at the echo
server:

```powershell
$env:ALERT_WEBHOOK_URL = "http://localhost:9999"
python app.py
```

In a third terminal, trigger a scan:

```bash
curl -X POST http://localhost:8080/api/v1/anomalydetector/scan
```

In the echo server terminal you will see the incoming POST request with the JSON payload
printed to stdout whenever the scan finds an anomaly. Because 30% of simulated snapshots
are anomalous, you may need to run `/scan` a few times.

## 10. Grafana Dashboard

The service exposes Prometheus metrics at `GET /metrics`. When deployed in Kubernetes
with the monitoring stack enabled, these metrics are automatically scraped by Prometheus
and visualised in a pre-built Grafana dashboard.

### Prerequisites

The monitoring stack must be deployed separately. From the `manifests/monitoring/`
directory:

```bash
# Install kube-prometheus-stack (includes Prometheus + Grafana)
bash manifests/monitoring/install_prometheus.sh
```

Confirm Grafana is running:

```bash
kubectl get pods -n monitoring -l app.kubernetes.io/name=grafana
```

### Access Grafana

```bash
kubectl port-forward svc/prometheus-grafana 3000:80 -n monitoring
```

Open your browser at `http://localhost:3000`.

Default credentials:
- **Username:** `admin`
- **Password:** `prom-operator`

### Find the dashboard

1. Click the grid icon (Dashboards) in the left sidebar
2. Search for **"AI Anomaly Detector"**
3. Click to open

The dashboard is automatically provisioned by Grafana's sidecar thanks to the
`grafana_dashboard: "1"` label on the ConfigMap in the `ts` namespace. No manual
import is needed.

### Dashboard panels

| Panel | Type | What it shows |
|---|---|---|
| **Total Scans** | Stat | Running count of `/scan` calls since the pod started |
| **Anomalies Found (last scan)** | Stat | Number of flagged services in the most recent scan. Green if 0, red if ≥ 1 |
| **Anomalies Over Time** | Time series | How many anomalies were found across the last hour |
| **Service Anomaly Scores** | Bar gauge | Per-service anomaly score (0–1) from the last scan. Green < 0.4, yellow < 0.7, red ≥ 0.7 |

### Enable or disable monitoring

In `manifests/helm/trainticket/values.yaml`:

```yaml
anomalyScanner:
  monitoring: true    # set to false to skip ServiceMonitor + dashboard ConfigMap
```

## 11. Troubleshooting

### Pod is in `CrashLoopBackOff`

```bash
kubectl logs -l app=ts-ai-anomaly-detector -n ts --previous
```

Common causes:
- **Import error** (`ModuleNotFoundError`): a package is missing. Check that the Docker
  image was built after the latest `requirements.txt`.
- **Port already in use**: another process is using port 8080. Check with
  `kubectl get svc -n ts`.

---

### `/scan` always returns `"source": "simulated"`

This means the service cannot reach Jaeger or Prometheus. This is expected when:
- You are running locally without a cluster
- The monitoring stack is not deployed in Kubernetes

To use live data, deploy Jaeger and Prometheus and set the correct URLs via environment
variables (see [Configuration](#6-configuration)).

---

### Grafana does not show the "AI Anomaly Detector" dashboard

Check the following in order:

1. **Is monitoring enabled?**
   ```yaml
   # values.yaml
   anomalyScanner:
     monitoring: true   # must be true
   ```

2. **Does the ConfigMap exist?**
   ```bash
   kubectl get configmap -n ts grafana-dashboard-ai-anomaly-detector
   ```
   If not, redeploy: `helm upgrade ts manifests/helm/trainticket -n ts ...`

3. **Does the ConfigMap have the right label?**
   ```bash
   kubectl get configmap grafana-dashboard-ai-anomaly-detector -n ts \
     -o jsonpath='{.metadata.labels}'
   ```
   You should see `{"grafana_dashboard":"1"}`.

4. **Is Grafana's sidecar scanning all namespaces?**
   Check `manifests/monitoring/prometheus-stack.yaml` for:
   ```yaml
   sidecar:
     dashboards:
       searchNamespace: ALL
   ```

### Webhook alert is not arriving

1. **Verify the URL is set:**
   ```bash
   kubectl get secret ts-ai-anomaly-detector -n ts -o jsonpath='{.data.ALERT_WEBHOOK_URL}' | base64 -d
   ```
   Should print your URL. If empty, `alertWebhookUrl` was not set in values.yaml.

2. **Test the URL manually:**
   ```bash
   curl -X POST https://your-webhook-url \
        -H "Content-Type: application/json" \
        -d '{"test": true}'
   ```

3. **Check pod logs for warnings:**
   ```bash
   kubectl logs -l app=ts-ai-anomaly-detector -n ts | grep webhook
   ```

### Python is not found on Windows

If `python` gives an error:

```powershell
# Check if Python is installed and find its path
where python
# or, if the Python Launcher is available:
py -3 -c "import sys; print(sys.executable)"

# Set a session alias using the path printed above
Set-Alias python "<path\to\python.exe>"
function pip { python -m pip @args }
```

### The Isolation Forest scores everything as anomalous

The model trains on 20 synthetic **normal** snapshots at startup. If you have retrained
it with anomalous data included in the training set, the baseline will be skewed.
Retrain with normal-only snapshots:

```bash
python src/simulate_traces.py --normal 30 --anomaly 0 --out-dir data/

python -c "
import json, glob
snaps = [json.load(open(f)) for f in sorted(glob.glob('data/sim_*_normal.json'))]
print(json.dumps({'snapshots': snaps}))
" | curl -X POST http://localhost:8080/api/v1/anomalydetector/train \
         -H 'Content-Type: application/json' -d @-
```
